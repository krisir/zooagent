# ADR-0009 应用助手改为与数据并排的三模式布局

- 状态：已被 [ADR-0013](0013-assistant-always-left-data-toggle.md) 取代（三模式换成单一数据页开关，助手固定在左侧）
- 日期：2026-10-20

## 背景

ADR-0008 把应用助手做成了右侧抽屉：需要时滑出，滑出时盖住数据。实际使用时问题很明显——和助手对话最需要看数据的时刻（"这条记录对不对"、"帮我把这几笔改成餐饮"），正是抽屉把数据挡住的时刻。用户要的是**一边看数据一边聊**，而不是在"看数据"和"用助手"之间来回切换。

同时，对话里的工具调用 trace 把每一步都摊开（读取模型 → 查询数据 → 新增记录 …）。对业务用户来说这些是管道，不是信息；一次"记一笔账"要刷三个 chip，读起来像调试日志。

## 决策

### 1. 助手停靠在应用视图里，不再覆盖数据

`app/ApplicationView.tsx` 变成两栏：

```
┌─────────────────────────────┬──────────────┐
│ 应用页头 + Tabs + 声明式 UI │ 应用助手     │
│ （表格 / 图表 / 表单）       │ （对话）     │
└─────────────────────────────┴──────────────┘
```

- 助手是 `<aside className="assistant-dock">`，`position: sticky`，和数据栏并排，永不遮挡内容。
- 复用 `ChatPanel`（同一个 `useChat` 流式通道），去掉抽屉外壳；`AppChatDrawer` 与右下角悬浮球一并删除。
- 窄屏（`max-width: 1080px`）自动改为上下堆叠，助手高度 `60vh`。

### 2. 三种模式，一键切换

页头一个 `Segmented`：

| 模式 | 效果 | 用途 |
| --- | --- | --- |
| 只看数据 | 隐藏助手，数据占满 | 浏览、核对、给别人看 |
| 并排 | 数据 + 助手 | 一边看一边改 |
| 只用助手 | 隐藏数据，助手占满 | 连续录入、长对话 |

- 默认是「只用助手」（ADR-0010）：从左侧列表点开助手就是对话，需要看数据时再切。
- 模式只影响布局，不影响会话：助手挂载时会从服务端取回该应用的历史对话（`useChat` 的 `GET /chat`），所以切换模式不会丢消息。
- 页头原来的「应用助手」按钮删除，模式切换取代它，避免两个入口语义重复。

### 3. 对话里默认不显示数据层工具

`features/chat/toolLabels.ts` 新增 `QUIET_TOOLS`：`list_models` / `describe_model` / `list_actions` / `query_records` / `aggregate` / `create_record` / `update_record` / `delete_record` / `run_action`。

- 这些 chip 在转录里隐藏，但仍然照常执行、仍然记录在消息元数据里（排障时还在）。
- **失败的工具永远显示**（`ok === false` 不过滤），写入被拒绝这类事不会静默。
- 结构类工具（创建应用 / 定义模型 / 定义业务操作 / 生成界面 / 配置专属助手）在**执行过程中**显示：主助手搭应用时，进度是用户真正关心的信息。
- **一次只显示一个 chip**：新的工具调用把上一个顶掉（`chip-in` 0.18s 淡入 + 上移），不并排成一行——过程提示不该在气泡里堆成标签墙。
- **工具 chip 是过程提示，不是转录内容**：助手一旦产出最终产出回复，该轮的所有 chip 立刻消失，只留对话本身（元数据仍保留，用于排障）。

### 4. 回复统一进泡泡，并按 Markdown 渲染

- 助手回答是**一个可见的气泡**（浅灰绿底 `#f4f7f3`、14px 圆角），用户消息是同样的形状换色 —— 谁在说话一眼能分清，长回复也不会糊在面板底色上。
- 回复按**基础 Markdown** 渲染：标题、无序/有序列表、`行内代码`、代码块、引用、分隔线、**加粗**、*斜体*、[链接](https://example.com)、单换行。
- 渲染器是自研的 `components/Markdown.tsx`（约 200 行，零依赖）：离线优先的打包版不值得为几个语法引入 react-markdown + remark（约 +100 KB）。输出全部是 React 元素，不用 `dangerouslySetInnerHTML`，模型输出无法注入 HTML。
- 输入框是对话的"驾驶位"：挂载即聚焦，发送后、回复落地后都保持焦点；流式回复期间**不禁用**输入框（禁用会夺走焦点和光标），只把发送按钮置灰，避免"每发一条就要点一次输入框"。
- 注意：内联解析必须每次新建 `RegExp` —— 解析是递归的（列表项里还有加粗），共享的 `/g` 正则会因内层调用重置 `lastIndex` 而让外层死循环（曾导致标签页卡死，已修）。

## 代价与边界

- **数据区变窄**：并排模式下应用内容只剩约 800px（内容上限 1200）。宽表格在并排模式下会横向压缩，需要看全时切到「只看数据」。
- **模式不持久化**：目前是会话内状态，重开应用回到默认「并排」。等偏好模型进服务端再考虑记住。
- 隐藏工具 chip 后，「只看数据」以外的页面在助手思考时只会显示「正在想…」，没有逐条进度——这是刻意的取舍：宁可安静，也不要噪音。

## 验证

- `cd apps/desktop && pnpm build`（tsc + vite）通过。
- `cd backend && uv run pytest` 通过（71 个用例）。
- `scripts/dev/capture_ui.py` 覆盖应用视图的三种模式，跑完无 JS 异常与控制台错误。

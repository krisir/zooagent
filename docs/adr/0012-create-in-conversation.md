# ADR-0012 创建助手只在对话里发生：先问清楚，确认后才动手

- 状态：确定（取代 ADR-0008 第 4 节的三段式创建抽屉）
- 日期：2026-10-20

## 背景

界面上有两条创建助手的路径：左栏的「＋ 新建助手」按钮（打开 `CreateAssistantDrawer`），以及在主助手对话框里直接说需求。抽屉本身是一段**写死的脚本**——固定的四个方向、固定的追问、固定的"收到，我会先做一个简单版本"——它不调用模型，只是在最后把拼好的一段文字丢给主助手。于是出现了两个问题：

1. **同一件事两个入口**，用户不知道哪个才是"真的"；抽屉里的对话看起来像 AI 在回复，其实不是。
2. **需求澄清发生在 LLM 之外**。抽屉问的三段和真正建应用需要的字段（记什么、怎么统计、哪个操作要一键完成）对不上，模型拿到一段泛泛的描述，只能自己猜着建。

## 决策

### 1. 删掉「新建助手」按钮与创建抽屉

- 左栏 `.navlabel-action`（＋）移除，`CreateAssistantDrawer` / `Drawer` 组件与相关 CSS 一并删除（`overlay` / `drawer*` / `stepper` / `coach` / `choices` / `mini-input` / `quick-hint` 等）。
- 创建助手的唯一入口是**主助手对话框**：左栏顶部的「主助手」，或任何页面里「让主助手升级」。

### 2. 主助手的提示词改成三段：先问、再确认、后创建

`backend/src/zooagent/agents/prompts.py` 的 `PRIMARY_PROMPT` 工作流程重写：

| 阶段 | 要求 |
| --- | --- |
| 第 1 步 问清楚 | 先 `list_applications`；然后一次问一组、最多 3 个问题，问三件事：用来干什么 / 一条记录有哪些信息 / 最常用的操作或想看到的统计。给例子、不列问卷、能从上下文推断的不问 |
| 第 2 步 复述确认 | 用 3-5 行复述理解（解决什么、记什么、页面看到什么、哪些一键完成），最后明确问「就按这个建，可以吗？」 |
| 第 3 步 创建 | 只有用户明确同意后，才 `create_application → define_model → define_action → set_pages` |

硬性规则同步加了一条：**用户确认前不得调用任何写结构的工具**。用户说「不用问了，直接建」可以跳步。

### 3. 离线模式保持模板直建

`offline` 规划器是确定性模板，不会提问也不会确认——它的定位是"没有模型时也能跑通"，与 LLM 的对话式澄清不冲突。mock 同理（只用于 UI/回归测试）。

## 代价与边界

- **没有模型时体验割裂**：离线模式一句话就建好，接上模型后反而要先回答两三个问题。这是有意的——模板只能覆盖少数场景，真实需求需要澄清。
- **多一轮对话**：用户不再"点几下就建"，但换来的是建出来的东西更贴近需求，减少"建完才发现字段不对"的返工。
- **提示词约束是软的**：模型仍可能跳过提问直接建。回归靠 `backend/eval`（结构校验）与人工验收，不靠前端拦截。

## 验证

- 前端删除后 `pnpm build`（tsc + vite）通过；无头浏览器左栏只剩「主助手 / 助手列表 / ⚙」。
- 真实模型（DeepSeek）实测三步：
  1. 「我想做一个客户回访记录助手」→ 只调用 `list_applications`，回复 3 个澄清问题，应用列表不变。
  2. 一次答完细节（字段 / 枚举 / 想要的统计）→ 不调用任何写工具，只复述 + 问「就按这个建，可以吗？」。
  3. 「可以，就这样建」→ `create_application → define_model → define_action → set_pages → set_app_agent`，应用建好。
- 回归测试 `test_agentscope_runtime_replays_history`：多轮上下文必须真的送到模型。顺带修掉一个隐藏 bug —— `AgentScopeRuntime` 里 `agent.observe(observed)` 没有 `await`，历史一直被丢弃，导致"下一轮忘记上一轮"（澄清流程根本走不通）。
- `backend && uv run pytest` 全过（prompt 边界测试仍在）。

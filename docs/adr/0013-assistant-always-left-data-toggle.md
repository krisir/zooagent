# ADR-0013 应用页只有一个开关：助手常驻左侧，数据页可折叠

- 状态：确定（取代 ADR-0009 的三模式布局与 ADR-0010 的默认「只用助手」）
- 日期：2026-10-20

## 背景

ADR-0009 给应用页做了三模式切换：`只看数据 / 并排 / 只用助手`，用一个 Segmented 摆在数据页页头。ADR-0010 又把默认值改成「只用助手」，理由是"点开助手就该是对话"。

实际用下来这套控件不成立：

- 三个模式里有两个只是"数据在不在"的变体。助手从来不是可选项——没有一个用户会想"我要数据但不要助手"。
- 分段控件是文字的，占了页头最显眼的位置，为的却只是一个布尔量。
- 模式是会话内状态，切换助手/切回列表后行为不直观；数据页也常常不是用户第一眼想看到的东西。
- 助手的可见性绑在数据页页头，隐藏数据时就一起消失了，没法从对话侧把数据叫回来（旧实现只能靠 `chat` 模式里的复制品）。

## 决策

### 1. 助手常驻左侧，数据页是可选的那一半

```
[ 助手列表 ]  [ AI 助手（永远在） ]  [ 数据页（可折叠） ]
      240px            380px                剩余宽度
```

- DOM 顺序就是视觉顺序：`assistant-dock` 在 `appview-main` 之前。
- 助手面板宽度固定 380px（与 ADR-0009 一致）；数据页消失时助手占满整行（`flex: 1`），不留下半屏空白画布。
- 主助手首页（`PrimaryView`）是单面板，不复用 `.appview` 的两栏结构。

### 2. 唯一的开关：对话标题栏里的一个图标按钮

- 按钮在 `ChatPanel` 的 `headerExtra` 里，`<TableOutlined />`：数据页可见时是 text 按钮，隐藏时是 primary（填充）按钮——一眼能看出当前状态和"点它会显示数据"。
- 删除 `AppPanelMode`、`Segmented` 与 `mode-chat` / `mode-split` 系列样式；状态变成 `App.tsx` 里的一个 `dataVisible` 布尔量，默认 `true`。
- 应用页头（固定 / 让主助手升级 / 刷新 / 删除）留在数据卡里：它是"应用结构"的操作面，不属于对话。数据页收起时这些按钮一起收起，点图标即可回来。

### 3. 三列共享一条基线：卡片高度 = 助手列表高度

- 应用视图改成 full-bleed：`.content.app-content` 去掉内边距与 1200px 上限，`.appview` 高度 100%。
- 于是三张卡（助手列表 / 助手 / 数据页）都是 `100vh - 24px`，顶部都在 `y = 12`，列间距统一 12px。
- 页面本身不滚动（`.scroller` 无溢出）：数据页在自己的卡片里 `overflow-y: auto`，对话在自己的卡片里滚动。
- 窄屏（`< 1080px`）退回堆叠：助手在上（60vh）、数据页在下，恢复整页滚动，避免嵌套滚动。

### 4. 收起/展开都有动效

- **收起**（180ms）：数据卡先脱离文档流（`position: absolute`，钉在原位）淡出并右移 14px，助手同时从 380px 过渡到整行（`flex-grow` 过渡）。两个动作重叠，而不是等面板消失后助手才变宽；200ms 后卸载面板。
- **展开**（240ms）：数据卡一开始就钉在它最终的停靠位置（还在文档流外）淡入，助手则在下面用 `dock-show` 关键帧把 `flex-basis` 从 100% 收到 `380px`。
  为什么用关键帧：面板挂载和助手变窄发生在同一帧，`flex-grow` 过渡缺少"变化前"的值；`entering` 状态保留 260ms，结束时面板落回文档流，几何位置不变，看不到跳变。
- 窄屏（堆叠布局）`flex-basis` 作用于块轴，会变成高度动画，所以那里只保留淡入淡出，并把面板留在文档流内。
- `prefers-reduced-motion: reduce` 下所有过渡与关键帧关闭。

## 代价与边界

- **应用页头随数据页一起隐藏**：固定、让主助手升级、刷新、删除在"只聊天"时够不到。这是刻意的——它们都是结构操作，而不是对话操作。
- **开关不按应用记忆**：`dataVisible` 是会话内状态，切换助手会沿用当前选择。持久化留给偏好模型上服务端之后再做（同 ADR-0009 的取舍）。
- **助手自然变宽**：数据页收起时对话宽度从 380 拉到整行。气泡本身有 `max-width` 约束，但长行阅读体验不如 380 窄栏，这是"隐藏数据后不留空白"的代价。
- **数据卡内部滚动**：`Popconfirm` / 下拉等浮层走 body 挂载，不受影响；但 `position: sticky` 之类依赖页面滚动的效果在卡片内不再适用。

## 验证

- `apps/desktop` 下 `pnpm exec tsc --noEmit` 与 `pnpm build` 通过。
- 无头浏览器（1440×900）量测：`rail` / `assistant-dock` / `appview-main` 均为 `y=12、h=789`；助手 `x=264`、数据页 `x=656`；`.scroller` 无溢出；数据卡内部滚动 445px。
- 点助手标题栏图标：数据卡消失、助手变 1164 宽；再点一次恢复 380 + 772。
- 动效时间线（无头浏览器逐帧采样）：收起时助手宽度 `380 → 423 → 621 → 974 → 1081 → 1151 → 1164`、面板 opacity `1 → 0`；展开时 `1164 → 1047 → 657 → 507 → 408 → 380`、面板 opacity `0 → 1`。
- 900×800：助手 766×60vh 在上、数据卡在下，整页滚动。
- 主助手首页仍为单面板 1164×789；`capture_ui.py` 无 JS 异常与控制台错误。

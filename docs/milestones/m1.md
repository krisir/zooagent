### M1 的验收标准（设计文档原文）

> 不依赖 AI，开发者能够通过 JSON Schema 创建一个有客户、订单、字段关系和 CRUD 的可运行应用。

对应验证：

```bash
cd backend
uv run pytest tests/integration/test_api.py::test_authoring_data_without_ai -q
```

该用例完全不接触 AI：直接 POST 模型定义（含 relation）、写记录、查询、聚合、验证唯一约束与 409 冲突。

## M2 验收标准

> 普通用户说"帮我做一个客户管理应用"，系统能够自动创建模型和界面，立即开始录入客户。

对应验证：

```bash
cd backend
uv run pytest tests/integration/test_agent_flow.py -q
```

离线规划器走的是和真实 LLM 相同的工具链，因此这条链路对模型配置是等价的（换成真实模型后行为更强，但校验、事务、界面渲染完全一致）。

## 发布产物验证（macOS）

打包链路已实测通过：

```bash
scripts/build/build-sidecar.sh
cd apps/desktop && pnpm tauri build
```

验证结果：

| 项目 | 结果 |
| --- | --- |
| sidecar 单文件 | 约 46 MB（含默认随包分发的 AgentScope），可用 `serve --port N` 独立启动并提供内嵌前端 |
| `.app` 体积 | 约 56 MB（不带 AgentScope 约 29 MB） |
| 启动握手 | 壳解析 stdout 的 `ready` 事件，拿到随机端口 + 会话 token |
| 启动时间 | 约 3 秒（AgentScope 惰性导入，只在选用 `agentscope`/`mock` 配置时加载） |
| 界面 | `http://127.0.0.1:<port>/` 返回内嵌的 React 应用 |
| 端到端 | 在真实打包应用内通过主助手创建「个人记账」并写入数据；打包版内跑通 9 个工具的 AgentScope ReAct 调用 |
| 退出清理 | 关闭窗口后无遗留 `zooagent-backend` 进程（父进程看门狗） |

仍未做：代码签名与公证、DMG 美化、自动更新、Windows/Linux 安装包验证。
